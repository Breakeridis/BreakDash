# BreakDash v1.0.8

Android package-signature compatibility, passive radio startup, and diagnostics that survive an app restart.

## Installing on the head unit

If the existing updater stops with **Missing APK signature**, download **BreakDash-v1.0.8-armeabi-v7a.apk** from this release in a browser or transfer that APK to the head unit. Open it with Android's installer and install over the existing BreakDash to retain preferences. This one-time manual step is necessary because the previous updater cannot reach the installer. Compatible 64-bit devices use **BreakDash-v1.0.8-arm64-v8a.apk**.

## Updates

- Uses Android's modern signing-information API first, then requests legacy certificate information if the modern API returns none.
- Still requires readable certificates and an exact match to the installed signer set. Missing, changed or extra signers are rejected. Signer ordering does not affect equality. No signing keys have been changed.
- Retains package, increasing-version and supplied-checksum validation plus Android's installer confirmation.
- Saves the last update validation result, certificate-read method and public certificate fingerprints for the next previewed feedback report.

## Radio and Home

- Returning to the dashboard now reads radio settings and listens for status broadcasts without binding the tuner or sending a frequency-state request. This removes resume-time vendor interactions as a possible cause of returning to Radio.
- Seek, power, band and preset commands bind on demand after an explicit tap, with a bounded connection timeout. Bindings are still released when the dashboard is hidden.
- PS/frequency can update from passive settings/broadcasts. RT text becomes available after using a dashboard tuner command; it is not queried on every Home return.
- Task separation and default-Home handling remain in place. The underlying vendor Home/black-screen problem is not confirmed resolved until tested on the head unit.

## Feedback evidence

- Keeps up to 32 app-only lifecycle, window-focus and radio connection events across process restarts.
- Captures the most recent Java exception's type, causes and stack frames, then delegates to Android's normal crash handler. Exception messages, intent extras and URLs are not recorded.
- Captures installed-app signing information and last download validation details. Existing upload redaction and preview-before-send still apply.
- These records do not prove the cause of a native crash, firmware app switch, process kill or missing Home intent. No system-wide logcat, external task history, background service, or automatic upload is added.

After installing, open Radio and try both Home controls while audio plays. If it bounces back, return to BreakDash however possible and send feedback immediately. The persisted evidence can now distinguish more cases than the earlier in-memory trace. Also test dashboard tuner buttons and a subsequent signed update.

GitHub Actions runs Android builds, lint, signer-trust regressions, existing JVM/reporting tests, and ABI/signature checks. No local builds, app execution or tests are run.
