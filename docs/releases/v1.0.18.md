# BreakDash v1.0.18

Fixes the factory Bluetooth check returning Home without starting.

The previous version checked dashboard visibility immediately after dismissing the dialogs, before their dismissal callbacks had removed the panels. It could return early and leave feedback showing **Not checked** despite the button tap.

- Records the request immediately and starts it once the dashboard is resumed and all panels have closed. A short handoff timeout saves an explicit failure if that transition cannot finish.
- Adds a temporary dashboard notice for preparing, checking and completion, so progress is visible beyond the toast. Opening another panel or leaving the app cancels pending work and prevents a later automatic start.
- Records request/start/result events for feedback. The existing eight-second factory session, verified service/proxy, primitive status allowlist and cleanup remain in place.

Update through **Updates → Check again**. Open **Bluetooth → Diagnostics → Check factory Bluetooth status**. Returning to the dashboard is expected; stay there until its notice says the result was saved, then reopen **Diagnostics → Send feedback**.

This fixes starting and observing the check; factory-service access and KW906 compatibility still need the head-unit result. GitHub Actions verifies delayed-dismissal, cancellation, timeout and duplicate-tap regressions, existing tests, lint, both ARM builds and signing. No local builds or tests run.
