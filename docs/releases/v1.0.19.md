# BreakDash v1.0.19

Adds factory Bluetooth discovery and a separate BLE compatibility option in one update.

- **Scan factory Bluetooth** uses the installed factory SDK's verified search/stop methods, with a 12-second native search and finite dashboard-visible session. Runtime SDK discovery action constants supply the event filter; missing definitions are reported before searching.
- Recognized SDK device objects appear locally after reopening Bluetooth. Their transport is marked unverified. Selecting a factory result enables an explicit **Test BLE connection** using its address, bypassing Android discovery.
- **Scan BLE** handles modern single and batched results. **Scan BLE · compatibility** adds a separate legacy Android scan path. Both retain independent diagnostic summaries and observation counts. Compatibility can share the same firmware limitation and cannot report asynchronous errors; empty results are inconclusive.
- Feedback includes native start/stop confirmation, event/model counts and payload shapes, plus bounded BLE/GATT definitions from the actual resolved factory service APK. Names, addresses, opaque payloads and characteristic values are excluded.
- Discovery is user initiated. Leaving the dashboard cancels native work, releases its binding and requests stop for an accepted search; the existing worker guard prevents accumulation behind stalled SDK calls. No automatic retry, pairing, resets, calls or vehicle commands are added.

Update through **Updates → Check again**. Close other Bluetooth/OBD scans and disconnect the scanner from your phone temporarily. Under **Bluetooth → Devices**, run **Scan factory Bluetooth** and wait on the dashboard until the result is saved, then reopen Devices. Run **Scan BLE** and **Scan BLE · compatibility** separately. If the scanner appears as a factory result, select it and try **Test BLE connection**. Finally **Diagnostics → Send feedback**.

Factory discovery does not establish BLE transport. Native generic BLE/GATT support, Android error 3 resolution and KW906 communication still require head-unit validation. This release provides explicit discovery paths and evidence without guessing vendor callbacks or Parcel formats. Use the **armeabi-v7a** APK on the car unit.

GitHub Actions verifies discovery contracts, typed-device/privacy bounds, stop ownership and cancellation, existing regressions, lint, both ARM builds and signing. No local builds, tests or device execution are performed.
