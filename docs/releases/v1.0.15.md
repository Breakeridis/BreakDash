# BreakDash v1.0.15

More complete vendor Bluetooth evidence and clearer native status failures.

- **Inspect vendor SDK entry points** prioritizes the SDK classes found on the head unit, with constructor, static factory, inheritance and callback definitions. BLE/GATT/discovery methods rank ahead of ordinary controls; constants no longer fill the selection budget. Inspection reads definitions without initializing classes, invoking methods or reading field values.
- Ordinary Android and optional local-ADB status captures save independently. Failures retain the capture method and stage, distinguishing an unavailable ADB listener, a connection/authorization failure and a status-read failure. Raw dumps and exception details remain excluded from feedback.
- Expanded bounded report space preserves more SDK definitions. Closing, covering or clearing the screen still cancels diagnostic work; no background connection or scanning is introduced.

After updating through **Updates → Check again**, open **Settings → Bluetooth → Open Bluetooth → Diagnostics**. Run **Inspect vendor SDK entry points**, then **Capture Android Bluetooth status**. If TCP debugging is available and authorized, also run **Capture status through local ADB**. Use **Send feedback** even if a capture fails; both capture results are retained.

This diagnostic update supports the next vendor integration step. It does not yet repair the head unit's BLE scan-start error or provide live OBD data. Install **BreakDash-v1.0.15-armeabi-v7a.apk** on the car head unit; the separate ARM64 APK supports compatible 64-bit devices.

Verification runs only through GitHub Actions: synthetic SDK/non-initialization and capture-privacy regressions, existing tests, lint, both ARM builds and release-signature verification. SDK visibility, Bluetooth behavior and cancellation during real device operations still require head-unit checks.
