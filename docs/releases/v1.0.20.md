# BreakDash v1.0.20

Improves factory Bluetooth discovery decoding and distinguishes device-found results from scan notifications.

- Handles primitive name/address fields using immutable public extra-key definitions from the installed factory SDK. Key strings are resolved at runtime; arbitrary strings are never treated as addresses. Unsupported or conflicting definitions remain explicit.
- Normalizes valid colon, hyphen and compact Bluetooth addresses, rejects invalid/conflicting fields, and merges later names into the same local device row. Names and addresses remain in activity memory only.
- Counts each SDK discovery action separately. Start/end/status messages no longer appear as partial device-decoding failures. Actual device-found messages that cannot be read or mapped are reported separately.
- Feedback includes SDK field-symbol roles and fixed decoding outcomes without key literals, payload contents, names or addresses. Existing typed SDK device objects remain supported; scan timing, cleanup and BLE modes are retained.

After updating through **Updates → Check again**, run **Bluetooth → Devices → Scan factory Bluetooth**. Wait on the dashboard until the result is saved, then reopen Devices. If the scanner appears, select it and **Test BLE connection**. Finally **Diagnostics → Send feedback**; the report now shows whether any actual device-found events occurred and whether their fields were decoded.

This addresses factory result handling and evidence. It does not establish KW906 compatibility or repair the firmware's standard Android BLE scan failure. Exact runtime SDK field definitions and device-found messages still require the head-unit test.

GitHub Actions verifies primitive-field mapping, ambiguity/type/privacy handling, control-versus-device events, bounded local records, existing regressions, lint, both ARM builds and signing. No local build or test is performed.
