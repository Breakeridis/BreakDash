# BreakDash v1.0.16

Targets the concrete factory Bluetooth controller found in the latest head-unit feedback.

- SDK inspection now prioritizes the concrete controller and its actual utility-helper parent, including inherited connection, cleanup and callback definitions. The helper exception is restricted to that exact class and its nested contracts.
- Larger bounded allocations preserve more controller and feature methods. Service-intent definitions and controller-returning static factories rank first. Referenced dependencies move ahead of general managers.
- Identical complete captured schemas are referenced across factory APKs, preserving space for distinct implementations. Incomplete or differing definitions are retained separately, with explicit omission markers.
- New saved scans, inspections and status captures include their producing app version. The snapshot explains that saved results can predate an update, preventing older scans from appearing to be new attempts.

Update through **Updates → Check again**, then open **Settings → Bluetooth → Open Bluetooth → Diagnostics**, run **Inspect vendor SDK entry points**, and **Send feedback**. If you repeat scans, their new timestamps and producing version will identify those attempts separately from the saved older results.

This remains a read-only definition inspection: it does not initialize or invoke vendor SDK code, enable ADB, reset Bluetooth or implement an undocumented transport. The existing Android BLE scan-start failure is still unresolved. Android status access needs DUMP permission; optional local ADB needs a reachable, authorized daemon.

GitHub Actions verifies synthetic inheritance, priority, non-initialization, completeness and deduplication regressions, existing checks, Android lint, both ARM APKs and signing. Install the **armeabi-v7a** APK on the 32-bit head unit. Physical-device confirmation is still required.
