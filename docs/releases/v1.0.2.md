# BreakDash v1.0.2

Simpler controls for the head unit, with less reading and larger actions.

## New utility layout

- Three dashboard buttons: **Settings**, **Updates**, and **About**. The update notification now appears on Updates.
- Full-screen maintenance panels with **Back** for one level and **Close** to return directly to the cockpit.
- Four Settings tabs: **Appearance**, **Maps**, **Apps**, and **Device**. Theme selection is now under Appearance.
- Provider URLs, local ADB details, package commands, and release notes open separately instead of filling overview screens.
- CPU/RAM sampling runs only while **Settings → Device → Device health** is visible.
- About contains three large tiles: **Report a problem**, **Device info**, and **Credits**.
- Reporting previews a capture before sending; the encrypted upload contains that exact report and note.

## Clearer updates

- Shows installed/latest versions and explicit **Up to date**, **Update available**, or **Development build** status.
- Explains when a compatible APK is unavailable rather than leaving a disabled action unexplained.
- Development APKs are now labeled **BreakDash Dev**, with a **Get signed release** link for switching to regular releases. The signed release installs alongside the development app; preferences are separate.
- Existing package, version, checksum, and signing-certificate verification remain enforced for release updates.

## Downloads

- **Head unit:** `BreakDash-v1.0.2-armeabi-v7a.apk`.
- **Pixel 7 Pro / 64-bit ARM phones:** `BreakDash-v1.0.2-arm64-v8a.apk`.

Install over the existing signed release to retain preferences. In v1.0.0/v1.0.1, use **About → Check for updates**; after upgrading, use **Updates**. If About shows a version ending in `-dev`, install the signed APK directly and open the release app.

Builds, lint, JVM tests, receiver tests, APK signatures, and ABI checks run on GitHub Actions. Physical screen fit and touch behavior still need checking on the phone or head unit. Nothing was compiled or run locally.
